The research is back. Here's the parity gap between mobile, desktop, and web:

Mobile is monitoring/steering only — it can't execute code itself. It's a thin client that connects to cloud sessions, Remote Control (your local CLI/desktop), or Desktop dispatch. From mobile you can start sessions, watch progress, review diffs, and get push notifications, but you can't:

Use MCP servers, skills, plugins, or connectors
Run slash commands like /plugin, /resume, /config
Touch a terminal
Use file pane, @mention attachments, side chats, or inline diff comments
Use Manual or Bypass permission modes (only Accept-edits/Plan/Auto, and that varies by connection type)
Desktop is the fullest surface, with everything mobile lacks plus: all permission modes, parallel sessions via git worktrees, a visual diff viewer, integrated terminal/editor, browser pane, computer use (macOS/Windows), and SSH/WSL sessions.

Web (what I'm running as right now) sits between the two — same core capabilities as desktop for cloud sessions and subagents, but trades some interaction richness for one advantage: sessions persist on Anthropic's cloud, so you can pick them up from any device, including mobile.

So concretely: mobile is "far off" from both by design — it's meant for checking in and steering, not doing the work. Desktop and web are close in capability; desktop just adds local-machine features (terminal, file editor, worktrees) that a browser session can't offer.
