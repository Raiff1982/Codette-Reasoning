## What WAS landed

### 1. `Metrics` → `reasoning_forge/nexis_signal_engine.py`

`OneDrive_2!Nexus/import json.py` — a file named after a stray paste — is a
**divergent copy of the live engine**, not a relic. 63 symbols each, 47 shared.

- **it had, we didn't:** `Metrics`, `record_process_time`, `record_error`,
  `get_stats`, `get_metrics`, `init_sqlite`, and the tests `test_metrics`,
  `test_cleanup_backups`, `test_sanitize_input`
- **we had, it didn't:** `WordNetLemmatizer`, `lemmatize`, `ratio`, `acquire`,
  `release`, `retry`, `wait_exponential` — dependency-fallback shims the live
  copy grew

`process()` already measured `time.perf_counter()` on both return paths and
logged the result, so the duration existed but nothing could retrieve it.

`Metrics` was taken **verbatim**. The instrumentation around it is new and
deliberately minimal: `process()` became a wrapper delegating to
`_process_impl()` (a pure rename of the existing body, no logic touched), which
records timing in `finally` and counts errors in `except` **before re-raising**.
Counting a failure must not swallow it — that is covered by a test.

`get_metrics()` added as the public accessor. 10 tests in
`tests/test_nexis_metrics.py`.

### 2. `reasoning_forge/hoax_filter.py` — new capability

Extracted from `OneDrive_2!Nexus/Aegis234567.py`, which is **not a Python file**
— it is a chat transcript carrying four whole files: `hoax_filter.py`, a variant
`nexis_signal_engine.py`, `hoax_scan.py`, `test_hoax_filter.py`.

Repaired by the documented "prose appended after the last line of code" rule:
one trailing transition line dropped from the module, and 24 trailing lines of
README prose dropped from the test file. **That prose was not discarded** — it
carries the integration contract and is reproduced in the module docstring:
`process_news(text, source_url=...)` returning `result["misinfo_heuristics"]`,
thresholds `combined >= 0.70` blocked, `0.45–0.69` adaptive intervention, else
keep base verdict.

Measured on recovery, and it moves **both** ways:

| input | combined |
|---|---|
| the Saturn hoax post | 0.875 |
| a factual NASA/Cassini sentence | 0.0125 |

**NOT WIRED.** `process_news` does not exist on the live engine and has not been
added. Whether Codette applies a misinformation filter to her own output is a
stance decision, not a quality guard, and is hers — see the house rules in
`CLAUDE.md`.

Tests in `tests/test_hoax_filter.py`. The four original assertions are carried
over verbatim so the author's thresholds are what gets checked; the two-way
tests are new, because the recovered suite only ever asserted that a hoax scores
high and never that anything scores low.

## Three defects found in `tools/archive_diff.py`

The instrument the whole recovery leans on has the blind spot it exists to
prevent. Not fixed here; recorded.

1. **It dispatches on extension.** `extract_modules` branches on
   `low.endswith(".docx")` / `".pdf"`, so a container whose name lies is treated
   as plain text — the exact failure `CLAUDE.md`'s first rule warns about.
2. **`walk_containers(max_depth=4)`.** These archives nest to exactly 4, so it
   squeaked through. The next set may not.
3. **No third-party filter.** Run against `OneDrive_2` it reports `NEW=466`,
   dominated by a bundled virtualenv (`Nexus/aegis_env/Lib/site-packages` — pip,
   setuptools, urllib3, pygments). Filtering vendored code leaves 98 unique
   payloads carrying 148 novel symbols, which is the real signal.

A magic-byte sniffer additionally reached **554 files** the name-based walk
skipped, including 5 PDFs, 7 SQLite databases, 13 gzips and 13 tars.
